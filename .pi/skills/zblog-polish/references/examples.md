# 风格锚点与修改示例

## 从文章中保留的表达方式

### 从问题进入

来源：`content/posts/read-python-behind-the-scenes-5-how-variables-are-implemented-in-cpython.markdown`

> 通过这一章我们将尝试理解，下面这一行简短的 python 代码背后，究竟发生了什么？

后面直接跟 `a = b`。学习的是“具体问题 + 最小例子”，不要求每篇都套这句开场。

### 主动追问

来源：`content/posts/you-said-no-mcp.markdown`

> 但这带来了一个新的问题：为什么不提供一个不包含 MCP 的 Code Mode 呢？

这里的问题推进了讨论，而不是用问句制造悬念。润色时应保留真正影响理解的追问。

### 不替作者解决所有疑问

来源：`content/posts/macos_apps_2026.markdown`

> 假如多个应用使用相同的本地模型，会重复占用内存空间吗？

原稿中的真实疑问可以留下，不必追加一段未经核实的答案或泛泛感悟。

## 编辑示例

以下是用于说明编辑原则的示例，不是 Henry 的原话，也不代表新的产品测试结果。

### 去掉宣传包装

修改前：
> Pi Durable 标志着 Agent 从短暂交互迈向持久智能的全新阶段，为未来的协作奠定了坚实基础。

修改后：
> Pi Durable 保存任务的执行进度，进程重启后可以继续未完成的工作。

原因：说明机制，删除无法验证的评价；实际文章仍需在恢复部分保留安全重放等条件。

### 解释术语，而不是换一个术语

修改前：
> 应用状态与对话实现了原子一致性。

修改后：
> 应用状态和相关对话记录可以在同一个事务中更新，要么一起保存，要么都不保存。

原因：解释“原子”的具体含义，不把数据库保证扩大到付款等外部操作。

### 区分已有功能与新增机制

修改前：
> Durable 首次让 Pi 支持上下文压缩。

修改后：
> Pi 已有自动压缩；Durable 会提前在后台生成摘要，让对话在压缩期间继续。

原因：风格调整不能掩盖事实错误；比较时应核对相关版本的文档。

### 不编造个人感悟

修改前：
> 看到这个设计，我突然想起无数次通宵修复服务的夜晚。

处理：
> 作者未提供这段经历，删除；如果它是文章必需的素材，再单独请作者补充。

不要换成“我愣了一下”或“我也曾深受其害”。

## 行为检查用例

1. 输入：“给上一版加上 Harness 小节，返回全文。” → 保留其他部分，返回完整文章，不只输出新增小节。
2. 输入：“Long runs anywhere 的中文？” → 只给短译法，不触发长篇润色流程。
3. 输入：“按原文顺序，一个小节一行。” → 保持对应关系与行级列表，不擅自扩成多个教程章节。
4. 输入：“先标问题，不改。” → 只列具体问题与建议，不输出改写全文，不写文件。
5. 输入：“润色这个文件。” → 读取并在聊天中交稿；未明确要求写回，不修改磁盘文件。
6. 输入：“将润色稿写回这个文件。” → 先看状态、diff 和最新文件，只修改授权内容，不提交、不发布。
7. 输入：“去掉最后的版本免责声明。” → 删除该句；不顺便删掉安全重试、外部副作用等实质条件，不在新结尾补回同义句。
8. 输入包含链接、代码、front matter 或 Mermaid → 保留有效语法与语义，不为口语化改坏标识符或代码。
9. 输入没有作者观点或亲历 → 不新增“我认为”“我以前”“我测试后发现”等归属于作者的内容。
10. 上游 speak-human-tw 无法联网获取 → 使用已读取的本地适配规则；不声称刚刚调用了上游完整 skill。

以上是人工验收标准，不是已运行的模型行为测试。
